# 🧩 Плагины FunPay Flux

Каталог плагинов для **FunPay Flux** — бота-помощника продавца funpay.com. Здесь любой может выложить свой плагин, а пользователи устанавливают его в приложении в разделе «Плагины» → «Сторонние плагины» → «Каталог».

**Требуются разработчики!** Если умеешь хоть немного JavaScript — напиши плагин, и им будут пользоваться все продавцы с FunPay Flux.

---

## Как написать плагин (5 минут)

**Язык:** JavaScript (Node.js 22+). Сборка и `npm install` не нужны. Пиши в любом редакторе, удобнее всего в **VS Code**.

1. Скопируй папку [`template/`](template) и переименуй её, например, в `my-plugin`.
2. Поправь `plugin.json`: `id` (как имя папки), `name`, `author`, `description`, `permissions`.
3. Напиши код в `main.js`.
4. Проверь у себя: FunPay Flux → «Плагины» → «Сторонние плагины» → «Установить свой» → **Папка разработчика** → путь к папке → «Подключить» → включи плагин. Сохраняешь файл — плагин перезапускается сам, а логи видны в журнале внизу окна.

### plugin.json

```json
{
  "id": "my-plugin",
  "name": "Мой плагин",
  "version": "1.0.0",
  "author": "твой_ник",
  "description": "Что делает плагин",
  "icon": "🧩",
  "main": "main.js",
  "permissions": ["chat"],
  "settings": [
    { "key": "answer", "type": "text", "label": "Текст ответа", "default": "Привет!" }
  ]
}
```

| Поле | Что это |
|---|---|
| `id` | латиница в нижнем регистре, цифры и дефис; совпадает с именем папки |
| `version` | `1.0.0` — при каждом обновлении увеличивай |
| `permissions` | что плагину можно (ниже). Пользователь видит список до установки |
| `settings` | поля настроек в приложении. Типы: `text`, `textarea`, `number`, `toggle`, `select` (+ `"options": [["a","Вариант А"]]`), у каждого можно указать `help` |

**Разрешения:**

| | |
|---|---|
| `chat` | читать сообщения покупателей и отвечать в чат |
| `orders` | оплаченные и подтверждённые заказы |
| `reviews` | новые отзывы |
| `notify` | уведомления в Windows и Telegram |
| `network` | ходить в интернет (свои API). Пиши, если используешь `fetch` |

### main.js

```js
module.exports = (flux) => {
  flux.command("!привет", (msg) => flux.reply(msg, flux.settings.answer));

  flux.on("order", async (order) => {
    // { orderId, chatId, buyerName, buyerId, amount, title, quantity, lotId }
    await flux.say(order.chatId, `Спасибо за заказ #${order.orderId}!`);
  });
};
```

| API | |
|---|---|
| `flux.on("message", fn)` | сообщение покупателя `{ chatId, text, buyerName, authorId, blacklisted }` · нужно `chat` |
| `flux.on("order", fn)` | оплачен заказ · `orders` |
| `flux.on("confirmed", fn)` | заказ подтверждён `{ orderId, chatId }` · `orders` |
| `flux.on("review", fn)` | отзыв `{ orderId, rating, chatId, buyerName, changed }` · `reviews` |
| `flux.on("settings" / "start" / "stop", fn)` | смена настроек, запуск, остановка |
| `flux.command("!cmd", (msg, args) => …)` | команда в чате |
| `flux.say(chatId, text)`, `flux.reply(msg, text)` | написать в чат (до 20 сообщений в минуту) · `chat` |
| `flux.notify(title, text)` | уведомление · `notify` |
| `flux.settings` | значения настроек |
| `flux.storage.get(key, def)`, `.set(key, value)`, `.delete(key)`, `.all()` | свои данные, до 2 МБ, переживают перезапуск |
| `flux.log(text)`, `flux.log.ok / warn / error` | журнал бота |

Можно писать ES-модулем: файл `main.mjs` и `export default (flux) => { … }`. Подсказки для VS Code — [`template/flux.d.ts`](template/flux.d.ts).

Примеры: [`plugins/ping-pong`](plugins/ping-pong) (команда в чате), [`plugins/order-counter`](plugins/order-counter) (заказы, хранилище, уведомления).

### Песочница

Каждый плагин работает в отдельном процессе с ограничениями Node.js. Он **не видит** вход в FunPay, пароли, ключи и файлы бота, **не может** записывать файлы и запускать программы — только то, что в `flux`. Можно `fetch`, `setTimeout`, `setInterval` и свои файлы из папки плагина (`require("./utils.js")`). Не клади в плагин `.exe`, `.dll` и другие исполняемые файлы — такой плагин не пройдёт проверку.

## Как выложить плагин

1. Сделай **Fork** этого репозитория (кнопка вверху справа).
2. Добавь папку `plugins/<id>/` со своим плагином. Не меняй файлы вне своей папки.
3. Открой **Pull Request**. Бот сразу проверит `plugin.json` (зелёная или красная галочка), а владельцу каталога придёт уведомление.
4. После Merge плагин появится в каталоге со значком **🟡 Не проверено**. Когда владелец протестирует его — значок сменится на **✅ Проверено**.
5. Обновление — тот же путь: поменяй код, увеличь `version`, пришли PR. Каждая новая версия снова проходит проверку.

## Для владельца каталога (настройка один раз)

1. Создай на GitHub **публичный** репозиторий `funpay-flux-plugins` и загрузи туда содержимое этой папки.
2. **Settings → Pages → Source: GitHub Actions.**
3. **Discord:** в канале → «Настройки канала» → «Интеграция» → «Вебхуки» → «Новый вебхук» → «Копировать URL». Затем на GitHub: **Settings → Secrets and variables → Actions → New repository secret**, имя `DISCORD_WEBHOOK`, значение — этот URL.
4. **Actions → «Опубликовать каталог» → Run workflow.** Каталог появится по адресу `https://<ник>.github.io/funpay-flux-plugins/catalog.json`. Этот адрес впиши в приложение («Сторонние плагины» → «Установить свой» → «Адрес каталога») или вшей в сборку (`PLUGINS_CATALOG_URL` в `worker/src/config.js`).

**Что приходит в Discord:**
- 🧩 «Прислан плагин — надо посмотреть» — кто-то открыл PR (со ссылкой на него).
- 🟡 «Ждёт проверки» — плагин или новая версия попали в каталог без проверки.
- ✅ «Одобрен» — после твоего одобрения.

**Админ-панель:** `https://<ник>.github.io/funpay-flux-plugins/admin/`. Вход — fine-grained токен GitHub (только этот репозиторий; Contents и Actions — Read and write). В админке можно:
- добавлять плагины из zip;
- менять название, значок, автора, описание, категорию;
- ставить цену или «бесплатно», ссылку «где купить», «в топе» и «скрыть»;
- одобрять и удалять плагины, смотреть код;
- выдавать и отзывать ключи для платных плагинов.

Сохранение — это коммит в репозиторий, каталог обновляется сам примерно за минуту. Секретный ключ подписи хранится только в браузере: **скачай резервную копию** на вкладке «Ключи».

**Как проверять:**
1. Посмотри код в PR: нет ли отправки данных покупателей на чужие сайты, спама, обмана.
2. Нажми Merge. Плагин появится в каталоге как «Не проверено».
3. Установи его у себя из каталога (или ссылкой «Скачать для теста» из Discord) и протестируй.
4. **Actions → «Одобрить плагин» → Run workflow → id плагина.** В каталоге появится ✅.

Одобряется конкретная версия (по отпечатку файлов). Если автор тихо поменяет код, значок снова станет «Не проверено».
